## 三、UI 缺失的整个页面（UX 视角）

当前独立前端 **只有"游戏中"这一个状态**。以下整个页面/流程完全缺失：

| 页面 | 用途 | 包含元素 |
|------|------|---------|
| **标题/入口页** | 启动时的第一个画面 | Logo、"新游戏"/"继续"/"加载"按钮 |
| **模组浏览器** | 浏览和选择要玩的剧本 | 模组卡片（封面、标题、难度、时长、标签）、搜索/过滤栏 |
| **角色选择器** | 创建/导入/选择调查员 | "快速开始"/"创建新角色"/"从 ST 导入"三选一 |
| **角色创建向导** | 6-8 步车卡流程 | 属性掷骰→选职业→分配技能→写背景→选装备→确认 |
| **设置面板** | AI 模型、KP 声音、模组参数配置 | 模型选择器、温度滑块、KP 风格预设、难度调整 |
| **会话管理器** | 存档/读档/删除 | 存档列表（含时间戳、模组名、角色名） |
| **完整角色卡** | 查看和编辑全部数据 | Tab 分页（属性/技能/战斗/装备/背景/笔记） |

## 七、Wave 0 具体实施路径（接下来做什么）

修复顺序按依赖排列，每步可独立验证：

### Step 0.1：注入 KP System Prompt（后端改动）

**文件**：`plugins/coc-rules-engine/index.js` 的 `/generate/chat` 端点

```
改动前：直接转发 messages 给 LLM
改动后：
  1. 读取 kp-prompts → buildSystemPrompt(scene, charSummary)
  2. 将 system prompt 作为 messages[0]{role:'system', content:systemPrompt}
  3. 再附加 user 的原始消息
  4. 发送完整 messages 数组给 LLM
```

**验证**：curl 发一条消息，检查 AI 回复是否以 CoC KP 口吻（感官细节、不出现"有趣的"/"建议你"等禁止词）

### Step 0.2：连接 Two-Pass 生成（前后端改动）

**文件**：`/generate/chat` + UI `sendMessage()`

```
后端：
  - /generate/chat 新增 checkResult 和 sanResult 可选字段
  - 有 checkResult → 调 two-pass-generator 生成 Pass1→Pass2 → Pass2 作为 user content
  - 有 sanResult → 同上

前端：
  - 点技能按钮 → 先调 /roll/skill-check 获取骰子结果
  - 再调 /generate/chat 时附上 checkResult
  - AI 回复中包含正确骰子结果的叙述
```

### Step 0.3：场景 Exit 按钮（前端改动）

```
UI 侧边栏场景区增加：
  - 读取 /scene/current 返回的 exits 列表
  - 渲染为可点击按钮（如"进入鬼屋"）
  - 点击调 POST /scene/transition
```

### Step 0.4：角色持久化（前端改动）

```
页面加载时：
  - 尝试 GET /character/pregen（预建角色）
  - 有 → 加载到 char 对象，渲染 UI
  - 无 → 调 POST /character 创建预建角色

SAN/HP 变化时：
  - 调 PUT /character/:id/san 和 /character/:id/hp
```
