# ST-CoC 重构实施计划

> **注意**：本文档中的步骤描述是**实施参考**，不是最终代码。每个步骤在具体实施时，仍需通过 Plan Agent 做更详细的分解和更精确的代码设计。

## 目标

将当前"冒险游戏"风格的系统重构为真正的 **TRPG 跑团平台**。

核心转变：
- 从"点击按钮推进场景" → "对话驱动叙事"
- 从"单角色" → "多角色队伍 + AI 托管"
- 从"预设场景流程" → "KP 自由裁定"
- 从"两栏布局" → "三栏布局（左队伍 / 中聊天 / 右工具）"

## Wave A — 移除场景出口，对话驱动 KP

**文件**：前端 `st-coc-ui/index.html`，后端 `plugins/coc-rules-engine/scene-manager.js`

### A1. 移除前端"行动方向"相关代码
- [ ] 删除 `loadScene()` 中的场景出口渲染逻辑
- [ ] 删除 `transitionScene()` 函数
- [ ] 删除场景出口 CSS
- [ ] 删除侧边栏中"行动方向"相关的 HTML 生成代码

### A2. 重构后端场景系统
- [ ] 修改 `scene-manager.js`：场景不再有固定的 `exits` 字段
- [ ] 场景变为"描述容器"——包含 read_aloud（朗读文本）、npcs、clues、keeper_notes
- [ ] KP 系统提示词不再包含"当前可用的行动方向"
- [ ] KP 被指示：描述场景后等待玩家行动，而非提供选项菜单

### A3. 修改 KP 系统提示词
- [ ] 在 `kp-prompts.js` 中移除所有"列出可选行动"的指令
- [ ] 添加"玩家用自然语言描述行动，你判断是否需要检定"的规则
- [ ] 添加"如果玩家行动需要技能检定，在回复中明确说明检定要求和难度"

### A4. 修改进入游戏流程
- [ ] `enterGame()` 发送场景开场白时，只描述场景，不提示"你可以做什么"
- [ ] KP 开场后等待玩家输入

### A5. 验证
- [ ] curl 测试：发送"我环顾四周" → AI 应描述所见，不列选项
- [ ] 前端：侧边栏不再显示"行动方向"按钮

## Wave D — 完整 CoC 车卡流程

**文件**：前端（单文件），后端 `POST /character` 已有基础

### D1. 车卡入口
- [ ] 标题画面增加"新建角色"选项（独立于"新游戏"）
- [ ] 或：新游戏 → 模组选择 → 角色选择 → "创建新角色"

### D2. 标准 7 步车卡流程

#### 步骤 1 — 选时代 & 创建方式
- [ ] 时代选择：1920s（默认）/ Modern / Gaslight
- [ ] 创建方式：掷骰 / 购点（460点）/ Quick-Start（固定值分配）

#### 步骤 2 — 生成/分配属性
- [ ] 掷骰模式：显示 3d6×5 和 2d6+6×5 结果，每项有"重掷"按钮
- [ ] 购点模式：8 项属性的滑块/输入框，总点数 460
- [ ] Quick-Start：8 个固定值 {40,50,50,50,60,60,70,80} 拖拽分配
- [ ] 实时显示衍生值预览

#### 步骤 3 — 计算衍生值（自动）
- [ ] HP = (CON+SIZ)/10
- [ ] SAN = POW
- [ ] MP = POW/5
- [ ] Luck = 3d6×5（独立投骰）
- [ ] DB/Build（查 STR+SIZ 表）
- [ ] MOV（自动计算）
- [ ] 年龄调整：40 岁后 MOV-1/10年

#### 步骤 4 — 选职业 & 分配职业技能
- [ ] 从 `GET /occupations` 加载职业列表
- [ ] 职业卡片：名称、信用范围、职业技能列表
- [ ] 选中职业 → 显示职业技能，可分配点数（EDU×4 或职业特定公式）
- [ ] 信用评级在当前职业范围内设置
- [ ] 剩余点数实时显示

#### 步骤 5 — 分配兴趣技能
- [ ] 点数：INT×2
- [ ] 可分配给任意非克苏鲁神话技能
- [ ] 所有 46 个技能的基础值预设
- [ ] 技能列表带搜索和筛选（按类别）

#### 步骤 6 — 背景故事
- [ ] 10 项标准背景条目：
  - 个人描述、信念/ ideology、重要之人
  - 意义非凡之地、宝贵之物、特点
  - 伤口/疤痕、恐惧症/躁狂症
  - 调查员经历
- [ ] 关键联系（用于 SAN 恢复）
- [ ] 姓名、年龄、性别、住所、故乡

#### 步骤 7 — 装备 & 确认
- [ ] 根据信用评级查表显示现金/资产
- [ ] 1920s 时代装备列表（可选）
- [ ] 武器选择（与职业技能关联）
- [ ] 一键提交 → `POST /character` + `POST /character/:id/skills`
- [ ] 成功后返回角色管理界面

### D3. 车卡 UI 模式
- [ ] 分步向导风格（有"上一步"/"下一步"按钮）
- [ ] 或 Dhole's House 风格（单页表单，自动计算）
- [ ] 建议：分步向导更适合新手，单页表单留给老手（提供两个入口）

## Wave E — 多角色 + AI 托管 + 多模型

**文件**：前端 + 后端 `POST /generate/chat` 增强

### E1. 角色管理数据结构
```javascript
var party = [
  {
    id: 'pc-001',
    name: '詹姆斯·卡特',
    type: 'pc',           // 'pc' | 'npc' | 'ai-pc'
    control: 'player',     // 'player' | 'ai'
    aiModel: null,         // null=player controlled, string=model name
    aiApiKey: null,        // API key for this character
    aiPersonality: null,   // ST-style personality description
    char: { /* CoC character data */ }
  }
]
```

### E2. 后端 — 多模型路由
- [ ] 扩展 `/generate/chat` 接受请求中的 `model` 和 `apiKey` 字段
- [ ] 支持按请求级切换模型（不再只读全局 settings）
- [ ] 如果请求指定了 `model`，使用该模型的 API
- [ ] 如果请求指定了 `apiKey`，使用该 key

### E3. 前端 — AI 托管角色
- [ ] 左栏角色卡片显示托管状态
- [ ] 点击角色卡片展开配置：
  - 选择模型（下拉：deepseek-v4-pro / kimi-k2.6 / gpt-4o / 自定义）
  - 输入 API key（或使用全局 key）
  - 编辑人格描述（自然语言）
  - 开关切换：玩家控制 / AI 托管

### E4. AI 角色行为逻辑
- [ ] 当 AI 托管角色轮到"行动"时：
  - 构造 prompt：`[角色人格] + [当前场景] + [其他角色最近对话]`
  - 调用该角色指定的模型
  - 生成角色对话或行动描述
  - 插入聊天流
- [ ] AI 角色可以：
  - 主动发言
  - 回应其他角色
  - 执行技能检定（由 KP 判断触发）
- [ ] KP 协调：先收集所有角色行动，再统一叙事

### E5. 多角色对话流程
```
玩家输入 → sendToAI(player_msg)
         ↓
      KP 处理
         ↓
  判断是否触发 AI 角色回应
         ↓
  AI 角色生成回应（使用其指定的模型）
         ↓
  KP 整合所有回应，产出最终叙事
```
